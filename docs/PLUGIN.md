# 媒体工作台 · DSH 插件

包名 `dsh-mek-media-workflow`，插件 ID 和内嵌技能名为 `media-workflow`。安装包自带完整技能和构建后的运行器、界面，不用再装一份同名技能或在宿主安装构建工具。

## 开始制作

1. 在 DSH 打开「媒体工作台」。从首页随手记灵感，或从「新建」写一句说明，选文章、图文或视频，附上真实资料。尺寸、受众、评审和发布设置按需展开；不打算发布时无需选择平台账号。
2. **当前对话制作**：让助手加载 `media-workflow`，按技能给出的任务根读取和导入阶段结果。这个选项不会自动唤醒对话助手，也不要求用户手写 JSON。**工作台模板制作**：选用宿主已配置的模型，由模型整理需求或生成结构化内容，再由执行器排版或合成；有图像输入能力的模型才会通过宿主附件服务获得实际图片。
3. 作品页先显示当前正文、排版预览或成片和下一步；过程、检查、旧版本和发布回执在「制作详情」。会话右侧「媒体任务」可以查看和评审同一任务，不必离开对话。

示例：给第一次使用的人讲清导出报表，横版两分钟，画面看清操作位置，口气平实，只制作不发布。提供真实产品画面、出处和明确重点，比填写每个转场或字号更重要。

「开始制作」可同时通过需求关，阶段评审方式在需求里确定。原生评审卡和工作台使用同一决定；修改已启动任务要重新提交需求，不能静默替换原始需求或历史产物。已提交但未核验的发布只查原请求，不自动重发。

## 首页、灵感、风格与复盘

- **首页**：计数是灵感、未归档任务和待处理任务的入口；「热门素材」仅预留 RSS 展示，未连接实际订阅源。
- **灵感墙**：可记录、编辑和删除想法，或加入链接、图片和视频（单附件最多 40 MiB）。从一张灵感做文章、图文或视频时，每种类型各对应一份任务；再次选同类型打开原稿，不重复建任务。附件通过同源鉴权路由上传与读取。
- **创作风格**：8 类、15 个内置写法，亦可在本机从用户提供的文本提炼自定义风格；这是写法，不是画面模板。任务开始时冻结工作区默认或本次选定的风格，以及已确认的写作规则。「重新提交需求」默认沿用原快照；另选风格会保留既有规则，勾选「重新读取所选风格和已确认规则」才重读规则。
- **复盘**：粘贴 JSON 或简单逗号分隔 CSV 导入阅读和互动数据，按本地统计生成建议，不自动抓取平台数据。再次导入替换输入数据集，不覆盖已确认规则。工作台需有已确认规则才可点导出，若同时启用了自定义风格，它也会写进导出的 Skill 文件；内置预设不写入，不会自动安装或启用。

## 交付与本地工具

- 文章原生交付 Markdown、HTML、可编辑工程和出处清单，不需要 FFmpeg/TTS；图文由本机 Chrome 在独立临时目录导出有序 PNG，不使用用户已登录浏览器会话。文章和图文画布支持文字、实际图片、形状、缩放、旋转、图层及页序，正文修改可进入新交付版本。
- 视频选用 FFmpeg 或已安装的 huashu-motion，均有模板边界；不调用文生图或视频生成模型。FFmpeg/ffprobe 用于合成与实测，NVENC、vips 等按任务和环境选用。定制成品和工程按 `embedded-skill/references/imports.md` 导入；专业工具的内容制作指导在 `embedded-skill/references/creation.md`。
- 素材理解可启用本地 OCR、语音转录、抽帧或有图像能力的模型。配置工具和模型目录不等于已经核实素材；结论仍需结合原件。工作台通常支持任务上传和导入单文件最多 2 GiB、一次交付导入最多 8 GiB；大文件分片保存并核对续传。工程用相对依赖；预览只读取当前版本已登记的资源，不运行文档内的脚本。
- 视频配音可选用户录音、支持显式 WordBoundary 的 Edge TTS，或支持句级时间轴的 MiMo（不伪造词级时间码）。MiMo Token 在「设置 → 制作偏好 → MiMo 语音」配置；配音和诊断从当前工作区设置同时读取 Token 与接口地址。新任务不保存 Token，任务详情和新版完整导出会过滤历史状态中的 Token。旧版下载链接需重新导出；之前已下载的包不会被改写。随包提供冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean 的预生成样本，试听不发起新合成请求。
- 发布用 PostFaro CLI、实际浏览器桥接与扩展。按文章、图文、短视频分别核对平台能力和账号；任务完成不代表作品已公开，只有实际回执或人工核验能确认发布结果。

## 数据与恢复

工作台读写设置中显示的实际数据根。默认 `$DSH_HOME/media-workflow`，未设置 `DSH_HOME` 时为 `~/.dsh/media-workflow`。工作目录切换只切读写位置，不迁移已有任务；宿主会向对话技能提供当前实际数据根和 CLI 路径，使用 CLI 时须显式传 `--root`。独立 CLI 不自动读取插件的目录指针。

任务、已保存草稿、素材和版本都在 `<数据根>/tasks/<taskId>/`；未提交表单由当前浏览器暂存。归档不移动任务，恢复后仍可沿用原 ID；额外交付目录只是正式产物的一份副本。灵感存 `ideas.json` 与 `ideas-media/`，风格存 `styles.json`，复盘与确认规则分别存 `metrics.json` 和 `rules.json`；导出的写作 Skill 默认位于 `skills/media-workflow-voice/SKILL.md`。`doctor.json` 和 `dsh.patch` 是启动诊断快照，不是宿主配置。

关闭浏览器不会停止宿主执行。切换目录、停用插件或变更版本前，先确认任务已经完成或暂停并等待实际子进程退出。宿主中断时保留历史、审批和原始发布请求，未知当作待核验，不重放。卸载不删除任务数据。

## 安装与回退

Node 要求 `>=22.16`；插件声明 DSH `>=0.2.1-rc.2 <0.3.0`，实际支持以目标宿主的验证结果为准。通过 DSH 的「插件 → 添加插件 → Git 仓库」安装时，填写 `https://github.com/MakeEpoch/dsh-mek-media-workflow`。从 `v0.2.9` 起，仓库根声明组合包并提供预构建文件，安装不需要运行构建脚本。旧 `v0.2.8` 标签的仓库根没有这个布局，安装旧版本请用它的 Release `.tgz`。

也可以在正确的 profile 用 DSH 官方插件管理安装已校验的冻结 `.tgz`，不链接源码。例如，使用实际文件替换下方路径：

```sh
dsh plugin --profile web add -w /absolute/path/to/dsh-mek-media-workflow-0.2.9.tgz --ignore-scripts
```

安装前检查目标 profile、运行中的任务以及必要的配置留存；安装后分别确认包解析路径、内嵌技能、界面和工作目录。适用的模型、素材工具和发布账号单独验证。需要回退时用宿主插件管理重新安装已验证的旧冻结包，不用旧 profile 整体覆盖现有配置。安装与回退说明不表示已经执行。

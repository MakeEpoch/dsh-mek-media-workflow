# 多风格、多类型内容工作流

2026-10-24。覆盖 AI、科普、自有产品宣传与生活内容。渠道作为交付选项，不能替用户决定作品类型或风格。调研来源与边界见技能 [趋势证据](../packages/media-workflow-skill/references/trends-2026-10.md)。

## 能力模型

分别记录五个维度：主题领域、作品类型、表达方式、视觉方向、交付渠道。支持用户自由描述，不要求为所有维度选择固定预设。

| 维度 | 示例 | 影响 |
| --- | --- | --- |
| 领域 | AI、科学、软件产品、生活、自定义 | 需要哪些证据、术语和真实素材 |
| 作品 | 文章、图文贴图、视频 | 执行步骤、编辑器、产物和检查 |
| 表达 | 科普、教程、实测、案例、个人叙事、生活记录、产品发布、轻松玩梗 | 信息主次、叙事、语气与结构 |
| 视觉 | 编辑排版、知识卡片、手账拼贴、真实操作、自然纪实、动态设计、自定义 | 版式、画面和制作工具 |
| 渠道 | 公众号、小红书、B站、快手、其他或仅交付 | 尺寸、文案、编辑器和发布适配 |

例如同一软件可以有“教程文章 + 操作截图”“案例贴图 + 知识卡片”“发布视频 + 动态设计”；生活素材也可以成为随笔、照片贴图、过程视频。避免用 news/product 同时代替类型、领域和风格。

当前原生视频向后兼容 brief.style。新增可选 creative.expression / visualStyle / tone / reference；未提供时不改变旧 brief 的结构及输入摘要。0.1.9 新增可选 work.type（article/image-post/video）和任务流程快照；未指定时仍按旧视频读取，不改变旧 brief 结构和摘要。

## 输入素材

素材池独立于作品，一个来源可被多个作品引用。保留原件、来源、采集时间、版本/摘要、可用范围与提取证据，并区分事实来源、表现素材、风格参考和生成素材。

- 文章/网页/文档：正文、段落定位与上下文；扫描件的 OCR 和人工核对分别记录。
- 图片/截图/贴图：原图、实际查看、主体与可用区；排版文字和业务示例不自动提升为事实。
- 视频/录屏：原片、片段时间码、关键帧、实际转录与声音。转录和关键帧不是整片已理解的证明。
- 音频/音乐/品牌：按实际用途保存出处与证据，原录音保留对齐来源。
- 风格参考：分析构图、节奏和语气，不能冒充为本人的素材、经历或事实。

外部核实适用于事实性主张；生活随笔中的自述与感受保留作者归属，不一律要求外部新闻证据，也不编造亲身体验。产品案例、实测和宣传主张分别记录证据等级。

## 按作品类型组织流程

| 类型 | 建议业务流程 | 主要交付 |
| --- | --- | --- |
| 文章 | 需求 → 素材理解 → 大纲/正文 → 配图与排版 → 预览检查 → 交付 → 可选发布 | 可编辑正文、排版 HTML、图片与出处 |
| 图文贴图 | 需求 → 素材理解 → 内容/页序 → 视觉排版 → 导出图片 → 移动阅读检查 → 交付 → 可选发布 | 有序图片、配文、可编辑页面/设计与素材 |
| 视频 | 需求 → 素材理解 → 脚本 → 镜头设计 → 音频/时间轴 → 工程 → 预览检查 → 成片交付 → 可选发布 | 视频、字幕、声音、工程、封面与证据 |

以上是业务阶段，不强迫每个内容都增加一个审批。需求中选择本次评审方式，内部取材、生成、检查、修正不新增用户确认；仅制作时跳过发布。没有配音的作品不检查 TTS，纯文章不依赖 FFmpeg，非品牌表达不强制索取 Logo。

## 原生执行设计与状态

1. **流程配置版本（0.1.9 已实现）**：任务保存 workflowProfile 和阶段定义快照。读取、依赖失效、恢复、进度分母、阶段标签与检查使用任务自己的流程，兼容原有十步视频任务。不能只在 UI 增加“文章”按钮，后台仍渲染 final.mp4。
2. **类型对应预览（0.2.0 已实现阅读、图组及自由画布编辑）**：文章看正文与排版，贴图看页序、缩略图和单页修改，视频看时间轴和画面。操作仍留在对话右侧，主动展开后进入完整工作台。
3. **统一产物协议（0.1.9 接入类型、role 与 MIME，导入仍有规范文件名）**：以 role + MIME + type + 输入/版本摘要识别正文、图组、成片、封面和工程，替代写死 final.mp4/cover.png 的逻辑。
4. **定制交付回纳（0.2.0 支持目录依赖、分片与大文件导入）**：支持实际文件与工程依赖的校验导入，创建新版本和对应评审。不得修改状态文件冒充导入，旧审批不能用于新产物。导出需能保留依赖并重开工程。
5. **素材理解任务（0.2.0 已实现 OCR、ASR、关键帧和实际图像输入）**：OCR、实际图像输入、视频转录/关键帧作为可追溯能力使用；能力不足时说明范围，不能把文件路径当作语义理解。
6. **发布类型适配（0.2.0 三种作品均已适配）**：先读取所选桥接的真实能力，再构建文章、图片组或视频的输入。沿用稳定 requestId 和未知结果核验责任；不能把所有作品都发成 shortVideo。

正文、图片、视频可以在同一项目中关联，但每个作品具有自己的版本、产物与审批范围。改变其中一件作品的标题或页序，不应该令其他作品的音频或所有原始资料失效。

## 各类内容的验收

文章检查论证、来源、重复空话、图文关系、链接与移动排版；贴图检查页序、字体与层级、裁切、图内事实和手机可读性；视频检查信息节奏、画面是否兑现分镜、声音/字幕/镜头关系和实际技术指标。平台尺寸/张数等以实际能力为准，不固化未经核对的规则。

“真实感”不是允许虚构经历；“科普感”不是术语密度；“高级感”不是统一深色背景；“热门”也不是单一标题公式。质量依据本次需求与作品证据，不承诺曝光或爆款。

## 0.2.0 完成范围

三种作品具有原生流程、实际交付、任务快照、右侧预览、版本和评审。素材处理接入本地 RapidOCR、faster-whisper、FFmpeg 音轨/关键帧；原始文件、提取工具、句段和词时间码、机器提取与未知项分别保留。图像输入经宿主附件服务验证，模型必须明确声明 image 能力；当前对话也可读取真实图片，导入观察后继续同一任务。

文章和图组的自由画布支持文字、图片、形状、拖动、缩放、旋转、配色、图层、页序与正文编辑；保存后产生新交付，后续包装读取本版正文。模型处理画布评审修改时基于本版工程，保留先前正文，不能靠改说明冒充实际变化。图组导出实际 PNG，并检查图片解码、尺寸与文字溢出。

单文件 2GB、交付包总量 8GB；大文件支持分片、重复分片校验、断点恢复与完成回读。目录依赖与显式摘要清单一并验证，缺失、越界或内容冲突会拒绝；预览只映射当前版本登记的 HTML/CSS/图像/字体资源，禁止执行脚本。专业工程的未公开二进制内部格式依提供的清单处理，不声称能解析任意外部软件工程。

发布适配 article、imageText 和 shortVideo。实际能力来自所选桥接，账户身份、输入摘要、稳定 requestId、发布确认和不确定结果核验责任保持一致；文章内嵌图片物化为本地媒体，图组按导出顺序提交。平台编辑器、审核和最终公共可见性依据实际回执，功能回归不会替用户发布测试内容。

静态画布、视频工程、模型识别和平台发布各有实际适用范围。复杂视频动画由专业工具制作并回纳；OCR/ASR 与图像观察仍需结合原件判断事实和表达，平台可能重新排版富文本，不能把工具成功当内容质量或流量保证。

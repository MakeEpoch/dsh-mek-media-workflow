# 作品类型与输入素材

## 分别确定输入、作品与渠道

文章、视频、图片既可能是输入，也可能是输出，不能从上传文件类型推断用户最终要什么。一个主题也可以衍生多个作品：解释文章、教程视频、可收藏的贴图各自组织内容；不是把同一份文字机械换尺寸。

内容领域（AI、科普、产品、生活等）、作品类型（文章、贴图、视频）、表达方式、视觉风格、交付渠道分别确定。领域和目标可以写在需求里，表达与视觉选择见 [styles.md](styles.md)。用户说“生活内容”不意味着自动选择快手，指定公众号也不意味着只能写长文章。

## 文章

依据主题选择深度解释、实操教程、测评对比、观点评论或个人叙事。用清楚的结构表达完整论点，配图承担解释、证据或情绪作用；不要用视频口播稿分段冒充文章。需要图片时，先判断真实照片、截图、图示或插画的用途，再取得或制作。

可交付正文 Markdown、排版 HTML、配图与出处清单；用户要求 Word 等格式时用环境中对应的文档能力。移动阅读检查段落长度、标题层级、图注、引用与链接。平台编辑器适配在内容确定后处理，保留可编辑正文，不只给整篇截图。

使用 work.type=article 创建原生任务，写作与编排分别生成请求，交付 article.html、article.md、publication.json 和 sources.json。右侧可直接阅读排版，正文与版式修改分别回到负责阶段。自动发布使用 article 输入并核对所选桥接能力，回执确认前不能声称已发布。

## 图文 / 贴图

包括单张解释图、图片组、知识卡片、照片配文、手账拼贴等。此处“贴图”主要指可发布的图片内容，不默认解释为聊天表情包；用户明确要表情或贴纸时再按该目标制作。

先决定每张图的阅读任务与页序：封面承诺与实际内容一致，内容页有清楚层级，相邻页之间有承接。按实际内容决定页数和尺寸，不强制所有作品九张图，也不把“文字很多”当成干货。照片组可以用真实场景与短注释组织，不必套知识卡片。

文字密集的排版、图示和多页内容优先使用可编辑的 HTML/CSS/SVG 等本地工程，再由可用工具导出实际图片；照片、插画或需要 AI 生成/编辑的位图使用环境中的图像能力。图片只有设计描述或生成提示词时属于方案，不能报告已经出图。没有相应导出或生成工具时，明确所缺能力，不交付占位图冒充成品。

可交付有序图片、配文、可编辑页面及素材清单。核对阅读顺序、手机尺寸可读性、跨页字体/色彩、图中文案与事实、裁切和来源标记。平台张数、比例和标题限制以目标平台实际能力为准。

使用 work.type=image-post 创建原生任务，交付从 page-01.png 开始的有序图片、gallery.html、article.md、publication.json 和 sources.json。PNG 使用本机 Chrome 在临时独立目录导出，检查尺寸与正文溢出；不读取用户登录会话。多张实际图片与配文分别交付，页序 JSON 只是编排方案。

## 视频

依据目的选择实操录屏、解释科普、实测对比、生活记录、场景故事或产品发布，按内容需要决定时长和横竖版。脚本、镜头、字幕、配音与音乐共同服务表达，不默认采用统一的“开场钩子—三点介绍—结尾关注”。

内置视频任务的操作见 [execution.md](execution.md)，制作方法与固定模板限制见 [creation.md](creation.md)。用户要求独立画面节奏、定制布局或复杂动画时，需要实际定制工程；不能只在分镜里描述。

## 素材理解与复用

| 输入 | 要理解的内容 | 保留的证据 |
| --- | --- | --- |
| 原文、网页、文档 | 观点、事实、上下文、时间与限定条件 | 原文、出处、截取范围；扫描/OCR 未核对时保留不确定性 |
| 照片、截图、贴图 | 主体、可读区、可裁切范围、示例数据、是否只是风格参考 | 原图、来源、使用范围、实际查看记录 |
| 视频、录屏 | 事件顺序、动作、关键帧、原声和可使用片段 | 原片、片段时间码、真实转录/关键帧与出处 |
| 音频 | 说话内容、说话人、语气、时间边界 | 原录音与真实转录/对齐来源 |
| Logo、品牌、音乐 | 角色、适用范围、与作品的关系 | 原始文件、品牌出处、音乐来源及使用说明 |

风格参考与事实来源分别使用；参考视频的剪辑、构图和语气可以分析，不据此认领别人的经历或搬运作品。用户生活素材不足时，不替用户编造亲身经历；产品宣传缺少实测时不写成独立评测。

原生素材收集接入文本/PDF、实际 OCR、语音转录、视频关键帧和图像输入；按 [实际素材理解](understanding.md) 使用已安装工具或当前助手处理，分别保留机器提取、实际观察和外部事实核实的证据。兼容当前任务时沿用 source/screenshot/logo/image/video/audio/music 等已有 role，不把设计中的新素材字段直接写入现有协议。

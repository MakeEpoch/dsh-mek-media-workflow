# 评审协议

策略在需求中声明，`review.mode` 必填。`gates` 默认关口来自 workflow.json，`none` 与 `steps` 的 gates 规范化为空。`editedAt` 只是说明时间，不代表用户授权或产物版本。

运行记录分别保存在 brief.json、state.json、review/ 与 receipts/。审批包含 taskId、runRevision、step、inputDigest、artifactDigest、决定、实际反馈和时间。多个界面共用同一个审批 ID，重复提交相同决定幂等。

DSH 的全局工作台、会话右侧面板和原生 plan-review 使用同一份审批。原生卡最多两个选项；完整“通过 / 要求修改 / 重做本步”在工作台卡片及展开的修改区提供。原生卡的讨论按钮不等于拒绝或重新制作；可以打开媒体工作台提交修改。

产物或输入发生变化时，旧审批不能作用于新版本。打回保留历史，只使当前关及实际依赖失效。封面和发布文案变化不应重采素材或重做旁白。重新打开页面不增加评审次数。

默认发布确认对三个档位都生效，并与发布关合并。`publish.confirm:false` 需有明确授权原文，不能仅凭布尔值推断许可。仅制作任务跳过发布关。

自动技术检查与人工评审是独立状态；缺必需输入、文件损坏、工具失败不能通过写入虚假审批解除。

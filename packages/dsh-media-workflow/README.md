# DSH 媒体工作流

安装包包含完整通用技能，两个包同步版本。安装后提供“媒体工作台”入口、会话右侧“媒体任务”、设置、评审与媒体预览，所有入口共用持久化运行器。

插件定位为多风格、多类型内容制作。文章、图文贴图和视频均接入原生流程。文章与图文采用无配音的九阶段流程，交付实际 HTML、Markdown 或 PNG，并保留可编辑工程。文章、图组与视频按各自类型适配 PostFaro，并保留发布确认和未知回执核验责任。

插件负责任务、素材、进度、版本、评审、预览与发布记录。内容制作还需要明确的表达方案、真实素材理解和成片检查；十步完成或工具检查全绿不代表作品质量已经验收。

首用先选择制作入口，检查实际工具能力。创建需求时一次确定评审方式；原生评审卡与工作台卡共用决定，任务中不提供静默切换评审模式的开关。

## 怎样提出制作需求

说明给谁看、看完应知道或能做什么、必须保留的重点、参考方向、时长与平台，再给真实来源和素材。无需为每个转场或字号填表；可先与对话助手讨论，由它整理需求。比如“给第一次使用的人讲清导出报表的操作，横版两分钟，画面能看清点击位置，语气平实，只制作不发布”。

文章、图文贴图、视频是作品类型；AI、科普、产品、生活是主题领域。表达方式与视觉风格可独立选择，语气与参考方向可补充；渠道只影响交付适配。news/product/original 分别表示事实原文、真实产品、原创生活的素材核对策略，不再拿来代表全部创作类型。

## 选择制作入口

- **当前对话**：让对话助手加载 media-workflow 技能，阅读原文、查看截图、完成脚本与分镜，并按同一任务根导入阶段结果。需要讨论和理解真实画面时优先使用。工作台的这个选项不会自动唤醒聊天模型；出现“由当前对话制作”时，继续让助手处理任务，不需要你手写 JSON。
- **工作台模板制作**：先在设置中配置 DSH 模型，再创建任务。模型生成结构化内容，内置执行器完成文章/图文排版或基础视频合成；图像理解会核对模型的 image 能力，并通过宿主附件服务提交实际像素；文字模型不会冒充看图。

设置会保存在任务创建时的执行配置中，后续更改全局设置只影响新任务。旧任务可继续由对话助手导入结果，不要为解除生成阻塞反复新建同名任务。

### 画面能力

文章和图文支持四种静态主题及 text/image/split 版式，可多图编排；自由画布进一步支持文字、图片和形状的拖动、缩放、旋转、图层与页序编辑，正文变更同步后续包装。图文使用本机 Chrome 在临时独立目录导出 PNG，检查尺寸与正文溢出，不接入用户登录会话。纯文章不依赖视频工具。

风格预设会进入脚本、分镜等生成指导，并保留在需求和版本中；这些选项不能突破执行器的实际画面能力。

当前 FFmpeg 是单素材、标题、同步字幕的固定版式；huashu 是可编辑的动态模板。两者都不是自然语言到任意画面的生成器，分镜里的复杂设计不会自动变成工程代码。

有明确的定制卡片、图表、分屏或复杂动效要求时，先在对话中确定专业工具的制作方案。完成预览和质检后，可在正式交付阶段导入实际文件与可编辑工程，登记新版本并按既定策略重新评审；文件约定见 embedded-skill/references/imports.md。具体制作指导随包提供于 embedded-skill/references/creation.md。

数据根默认 `$DSH_HOME/media-workflow`，CLI 可用同一根目录。卸载插件不会删除任务。先暂停任务，确认实际子进程退出；已发出的发布继续保留原请求及核查状态，不能重放。

兼容声明、开发与验证、安装回退和真实证据边界见源仓库 media-workflow/README.md。此包带构建后的 Client bundle，使用者无需在宿主安装构建工具。

## 使用

1. 安装前备份目标 profile 的清单、锁文件和 Cordis patch。通过 DSH 插件管理安装本地 tarball；例如 `dsh plugin --profile web add /absolute/dsh-media-workflow-0.1.0.tgz --offline --ignore-scripts`。Web 和 Desktop 分别选择目标，不覆盖整份 profile。
2. 打开“媒体工作台”，选择当前对话或工作台模板制作，检查本地工具。独立模型使用宿主已有配置，插件不保存 API Key。
3. 创建需求，选择文章/图文/视频、素材核对策略、资料与规格、评审档位和发布范围。发布默认在最终内容与账号展示后确认一次。
4. 任务与产物保存在数据根中；关闭页面后继续由 Host 执行。右侧“媒体任务”使用相同记录，可切回完整工作台。

本地工具由用户环境提供：图片导出使用 Chrome，视频使用 ffmpeg、ffprobe；TTS 可选 edge-tts（需支持显式 WordBoundary）或 MiMo 语音：MiMo 在“媒体工作台 → 设置 → 制作偏好 → MiMo 语音”中填写 Token，Token 只保存在数据根的 settings.json，不下发到浏览器、不写入任务目录，接口调用使用 OpenAI 兼容的 chat/completions。音色为下拉选择（冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean），旁边的“试听音色”播放随插件打包的预生成样本（由 MiMo 实际合成的同一句台词，离线可听，每次试听都不消耗 Token）；样本标签只标注实测基频对应的性别与音高。MiMo 不返回词级时间码，因此 MiMo 任务按每句真实音频时长对齐字幕（alignmentMethod 记为 sentence-boundary），明确要求词边界时不会伪造时间码；动态工程需已安装 huashu-motion；平台发布需 PostFaro CLI、实际桥接及兼容扩展。NVENC 和 vips 属于可选能力。工具缺失会明确显示，不自动安装或降级产品画面。

启动依赖检测保存到数据根的 doctor.json 和 dsh.patch 诊断快照；它们不是宿主的 Cordis 配置。扩展、账号和平台能力在选择实际浏览器后读取，未知状态不会当成已登录。

## 版本和恢复

支持的清单范围为 DSH `>=0.2.1-rc.2 <0.3.0`，当前实际 Web 验证基于 0.2.1-rc.2。Desktop、真实模型和具体发布平台需按其环境验收。

暂停与恢复保留阶段产物、审批和版本差异。需求修改形成新版本；仅重做受影响的阶段，有效批准可以复用。宿主中断的外部提交保留原 requestId 并进入待核验，不自动重发。已经产生发布尝试后，内容改版须重新提交需求。

停用或卸载使用宿主插件管理。卸载不删除任务；需要回退时重新安装之前的冻结包并回读解析路径与配置，不用旧 profile 整体覆盖后来新增的配置。

## 素材理解与大文件

在“素材理解”设置选择 auto/required/off、本地 OCR/ASR Python、已准备的语音模型目录与可选图像模型。模型仅支持文本时会保留图像未知项或按策略阻塞；OCR、ASR 和抽样帧各自保留证据，不能把抽样当整片观看或把 ASR 当强制对齐。

上传和交付导入支持单文件 2GB、单次交付 8GB，大文件分片保存并校验已上传分片。工程目录可保留相对依赖，HTML/CSS 只预览当前版本已登记的本地资源，禁止脚本。发布时按 bridge 的实时类型与平台能力检查参数及账号。
